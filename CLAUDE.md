# Booking Guard — project rules for Claude Code

## What this is
An AI agent that checks a database of customer bookings (gold-valuation events in Finnish cities),
finds problems, proposes fixes and drafts customer messages. It never changes data without explicit
human confirmation. Built as a portfolio project for a Data & AI Automation role.

## Stack
- TypeScript (strict), Node.js LTS, ES modules
- SQLite via `better-sqlite3`
- Tests: `vitest`
- MCP server: official `@modelcontextprotocol/sdk`
- No other frameworks unless I approve them

## Rules (always follow)
1. Every new function gets a test in the same step. Run `npm test` before saying a task is done.
2. Data changes ONLY inside a transaction. On any error — full rollback. Every applied change is written to `audit_log`.
3. `applyFix` requires a confirmation code. Default mode is dry-run.
4. Never print real emails or phone numbers to logs: mask them (`a***@example.com`, `+358 *** ** 12`).
5. All data is fake and generated by `seed`. Never add real personal data.
6. Customer messages are only written to files in `drafts/`. Nothing is ever sent.
7. Small steps: one feature per step, then stop and show me what changed. I review every diff.
8. Explain non-obvious code in 1–2 plain-English sentences — I need to be able to explain it in an interview.
9. At the end of every work session, update `PROGRESS.md` (done / next / open questions).

## Problems the agent detects
1. Duplicate bookings: same customer, same event
2. Double-booked slot: two bookings for the same event + time slot
3. Bookings for past or cancelled events
4. Empty or malformed contact data (email / phone)
5. Overbooked events: more bookings than event capacity

## Commands
- `npm run seed` — recreate the database with ~500 fake bookings and deliberate errors of every type
- `npm test` — run all tests
- `npm run check` — print found issues (CLI)
- `npm run mcp` — start the MCP server
